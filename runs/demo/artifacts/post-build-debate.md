# Post-Build Debate

Post-build Judge combines rubric weaknesses with agent risks; top improvements must address only clarity, feedback, and first success unless the scorecard exposes worse issues.

## Market Agent

Document evidence:
- Concepts must be explainable in one sentence or a short video pitch.
- Validate market appeal, target audience desire, and user value.
- MARKET 시장성과 트렌드 - 장르 시장 규모는 충분히 큰가?
- The first action must expose the core fun immediately.

Strengths:
- generated playable prototype
- simple theme readable in a short demo

Fatal risks:
- collection goal must be visible or the play may feel like a one-off puzzle

Concrete improvements:
- make the first reward visible
- show collection progress on the first screen

## Coreplay Agent

Document evidence:
- The first action must expose the core fun immediately.
- Use visual cues and responsive feedback to keep goals readable.
- The core loop should be simple, repeatable, and addictive.
- Map the first-session funnel from first tap to first win.

Strengths:
- one clear core action
- combo potential from repeated choices

Fatal risks:
- weak first-action feedback would make the game feel inert

Concrete improvements:
- add pulse feedback
- add a fast first success cue

## Level Design Agent

Document evidence:
- Map the first-session funnel from first tap to first win.
- Use visual cues and responsive feedback to keep goals readable.

Strengths:

## Production Agent

Document evidence:
- Minimize FTUE friction such as login, forced waits, and paywalls.
- Prefer concepts that can be prototyped quickly with low execution risk.
- Prototype is now concrete; post-build review prioritizes visible clarity and stability.

- static HTML prototype is feasible
- The first action must expose the core fun immediately.
